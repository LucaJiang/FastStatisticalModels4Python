Why it generalizes

Assignment-update pressure appears in broader iterative methods.

The main computational pressure is repeated distance work: N × K × d every iteration.
k-means is not the most advanced model, but it is a useful test case because the statistical and computational pressures are easy to see. The validation contract is fixed: same data, same initial centroids, same stopping rule, and comparable final inertia. The algorithm also becomes harder under overlap, imbalance, outliers, and higher dimension. Computationally, the repeated distance work scales with N times K times d every iteration. That lets us explain bottleneck shapes without turning Numba, NumPy, and JAX / A100 into a ranking.

Implementation shape

The same distance step can be expressed three ways

Same validation contract; three ways to express the distance computation.

Numba

Keep the assignment step as explicit loops.

@njit(parallel=True)
for i in prange(n):
    best = inf

    for k in range(K):
        dist = sqdist(X[i], C[k])
        if dist < best:
            best = dist
            labels[i] = k

Shape: loop-heavy CPU work without Python loop overhead.

NumPy

Rewrite distances as dense matrix algebra.

x2 = sumsq(X)[:, None]
c2 = sumsq(C)[None, :]

dist2 = x2 + c2 - 2 * (X @ C.T)

labels = argmin(dist2, axis=1)

Shape: readable array expression; heavy matrix multiply is BLAS-backed.

JAX / A100

Use the same array expression on device.

@jax.jit
def assign(X, C):
    x2 = sumsq(X)[:, None]
    c2 = sumsq(C)[None, :]

    dist2 = x2 + c2 - 2 * (X @ C.T)
    return jnp.argmin(dist2, axis=1)

Shape: large regular array work, only useful after validation and enough scale.

Same data. Same initialization. Same stopping rule. Then choose the expression that matches the bottleneck.
This slide is not about teaching full k-means syntax. It is here to make the benchmark interpretable. Numba keeps the assignment step close to explicit loops and removes Python loop overhead. NumPy rewrites the distance computation as dense matrix algebra; the code is NumPy, while the heavy matrix multiply is BLAS-backed underneath. JAX / A100 uses nearly the same array expression on the accelerator, but it is only useful after validation and enough scale. The validation contract is unchanged: same data, same initial centroids, same stopping rule, and comparable final inertia.

Code shape

Same permutations, different computation

Start with the readable loop; then rewrite the expensive repetition.

Reference loop

for r in range(R):
    labels_r = same_permutation_stream[r]
    stat[r, :] = group_difference(X, labels_r)

Optimized path

for W_batch in contrast_batches(
        same_permutation_stream):
    T = W_batch @ X
    counts += abs(T) >= abs(T_obs)
W_batch: batch_R × n X: n × p T: batch_R × p

Same permutation stream and p-value definition; the streamed path avoids the full R × p null matrix.

The optimized path does not change the statistical question: same simulated data, same permutation stream, and same p-value definition. The shape chips explain the batched matrix view: W_batch is batch_R by n, X is n by p, and T is batch_R by p. The streamed path avoids materializing the full R by p null matrix.
