\begin{column}{\colwidth}
  \begin{alertblock}{A workflow talk disguised as a performance talk}
    Statistical code does not usually start with the fastest kernel. It starts
    with a question: \textbf{can I trust this result?}

    \vspace{0.5em}
    We use simulation to build trust, then optimize only the computational
    pattern that simulation proves is expensive.
  \end{alertblock}

  \begin{block}{The simulation loop}

  \begin{block}{Why this matters}
    \begin{itemize}
      \item A faster implementation that changes the statistic is a different method.
      \item Big data can hide mistakes that small controlled simulations reveal.
      \item The right tool is the one that preserves statistical meaning while removing the real bottleneck.
    \end{itemize}
  \end{block}
\end{column}

\begin{column}{\colwidth}
  \begin{block}{Two workloads}
    \heading{k-means: iterative pressure}
    Lloyd's algorithm repeats assignment and centroid updates. It exposes
    Python loop overhead, temporary arrays, cold-start compilation, and
    high-dimensional scaling.

    \vspace{0.7em}
    \heading{Permutation test: resampling pressure}
    The statistic is simple, but $R$ independent resamples expose random
    generation cost, process copies, shared memory, and thread-level parallelism.
  \end{block}

  \begin{block}{Local evidence}
    \bigstat{numba}{10.8$\times$}{Numba over naive NumPy for k-means at $N=10^6$}
    \hfill
    \bigstat{threadteal}{0.17 s}{Free-threaded ThreadPool at $R=10\,000$}
    \hfill
    \bigstat{processorange}{833 MiB}{Child-process RSS in multiprocessing}

    \vspace{1.0em}
    \small
    Current local env: Python 3.12.2, NumPy 1.26.4, Numba 0.59.1, JAX 0.4.25
    on CPU. Python 3.14t is confirmed free-threaded.
  \end{block}

  \begin{block}{What changed when K and d grew}
    \begin{figure}
      \centering
      \includegraphics[width=0.97\linewidth]{../experiments/results/v2/kmeans_shape_k50_d100.png}
    \end{figure}
    \small

  \end{block}
\end{column}

\begin{column}{\colwidth}
  \begin{block}{Three memorable findings}
    \heading{1. Validate before optimizing}
    The k-means implementations share fixed initial centroids; a sklearn
    fixed-init check matches inertia to relative error $\sim 1.5{\times}10^{-16}$.

    \vspace{0.8em}
    \heading{2. Shared memory is a feature}
    For permutation tests, threads and Numba keep one in-process input array.
    Multiprocessing pays startup cost and carries worker copies.

    \vspace{0.8em}
    \heading{3. JAX is not magic CPU parallelism}
    JAX is excellent when the workload maps to XLA or accelerators. CPU
    \texttt{vmap} over random permutations is an honest anti-pattern here.
  \end{block}

  \begin{block}{Free-threaded Python: same thread code, different ceiling}
    \begin{figure}

    permutation code from 0.32 s to 0.17 s at 8 workers.
  \end{block}

\begin{minipage}{0.956\paperwidth}
  \begin{alertblock}{Decision guide}
    \begin{minipage}[t]{0.23\linewidth}
      \heading{Start with trust}
      Controlled data, fixed seeds, and a reference implementation define the
      statistic before any optimization changes the code.
    \end{minipage}
    \hfill
    \begin{minipage}[t]{0.23\linewidth}
      \heading{Fuse hot loops}
      When Python owns the inner loop, Numba is the most direct path to compiled
      scalar logic without changing the method.
    \end{minipage}
    \hfill
    \begin{minipage}[t]{0.23\linewidth}
      \heading{Watch memory shape}
      Broadcasting can create the right answer through the wrong temporary.
      Matrix identities and fused kernels reduce the real bottleneck.
    \end{minipage}
    \hfill
    \begin{minipage}[t]{0.23\linewidth}
      \heading{Choose shared data}
      For resampling, threads and free-threaded Python keep one input array;
      processes need an explicit memory budget.
    \end{minipage}
  \end{alertblock}
\end{minipage}
